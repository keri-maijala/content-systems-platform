## What was decided
See `DECISIONS.md` for full detail. Summary:
- Credentials in env vars, not repo
- No forced password reset (requires database layer)
- 12-hour JWT sessions in httpOnly cookies
- Rate limiting: 5 attempts / 15 min / IP

## Issues encountered

### CSS variables causing hydration failures
Using `var(--navy)` etc. in pages that Next.js statically renders caused React to fail silently — form handlers never attached. Discovered by comparing bare working version vs styled broken version. Fixed by replacing CSS variables with direct hex values in the login page and Nav. Main app unaffected (rendered dynamically).

### Next.js static rendering of login page
Next.js 14 was rendering the login page as a static page (`○` in build output), meaning no JavaScript ran on the client. Fixed with `export const dynamic = 'force-dynamic'` — not yet confirmed at end of session.

### ENV var not being read (false alarm)
Early in the session, `AUTH_JWT_SECRET` returned "server misconfigured." Turned out Vercel had autofilled the field with a different key (`sk_live_a12...`) during setup. Corrected manually. Added to setup checklist: always verify the value after saving an env var in Vercel.
